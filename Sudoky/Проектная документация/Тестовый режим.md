# TD-01 — быстрый тест завершения партии

Задание владельца от 11 октября 2026. Статус: реализовано; программные
проверки и сборки прошли, ожидается личная приёмка владельца.

Это отдельное разрешённое владельцем исключение из запрета менять игровую
механику при редизайне, ограниченное отладочной генерацией новой доски.

## Требования

- В настройках Debug добавить локализованный переключатель «Тестовый режим»
  / «Test mode», по умолчанию выключенный. Хранение через SettingsManager.
- Подпись объясняет: новые партии содержат одну пустую клетку.
- Во всех пяти сложностях новая партия и перезапуск при включённом режиме
  получают корректное Sudoku с 80 открытыми, нередактируемыми цифрами и
  ровно одной пустой редактируемой клеткой. Правильный ввод запускает
  существующий сценарий победы.
- Режим не преобразует уже сохранённую/возобновлённую партию.
- Выключенный режим сохраняет прежний обычный генератор и правила сложности.
- Переключатель и тестовая генерация ограничены `#if DEBUG`. В Release
  тестовая логика отсутствует и не активируется даже при сохранённом true.
  Для релиза не требуется вручную переключать пользовательскую настройку.
- Начисление XP, статистика, таймер, жизни, сохранения и экран победы работают
  по прежним правилам: тестовая победа тоже учитывается. Формат данных не менять.
- Убрать из SettingsView выбор цвета и его ненужный UI-helper. Существующие
  значения цвета, AppStorage и применение цвета в интерфейсе не удалять,
  не перезаписывать. Отдельных цветовых вариантов фактически нет.
- Стиль настроек: существующие PaperSectionCard/textStyle/loc; RU и EN.

## Исполнитель и проверки

Главный разработчик — чат «Ждать указаний руководителя». Руководитель код
приложения не редактирует. Область: SettingsView, SettingsManager,
SudokuGenerator, SudokuViewModel, новые строки и узкие проверки генератора.
Не менять главную, музыку, сад, рамку, начисления или навигацию.

Программно без симулятора проверить пять сложностей: одну пустую клетку,
80 фиксированных, уникальное решение, победу после единственного правильного
ввода; выключенный режим и сохранённую доску не затрагивать. Проверить Release
без DEBUG, в том числе отсутствие доступа к тестовой генерации.
По одной успешной компиляции Debug и Release: две конфигурации нужны именно
для подтверждения релизного исключения, без повторных успешных запусков.
Не запускать приложение/симулятор/UI-тесты. После отчёта — личная приёмка владельца.

## TD-02 — начать выращивание заново через сброс статистики

Запрос владельца от 11 октября 2026 после приёмки GARDEN-01. Статус:
реализовано, Debug/Release скомпилированы; ждёт личной приёмки владельца.
Это явное разрешение на сброс рабочего сада и XP
в пределах подтверждённого действия пользователя при тестовом режиме.

- Использовать существующую кнопку «Сбросить статистику» и подтверждение.
  Только в DEBUG при `SettingsManager.testModeEnabled == true`: сбросить
  статистику всех сложностей, рабочее дерево/выбор, доступные действия,
  максимум учтённой ступени и флаг первой посадки; XP = 0, currentLevel = 1.
  Первая посадка снова бесплатна, автоматического дерева нет.
- При выключенном режиме и в Release остаётся прежний сброс только
  статистики; сад, XP и ступень сохраняются. Сохранённое true в настройках
  Release не активирует расширенный сброс. Отмена подтверждения ничего не меняет.
- В тестовом режиме подтверждение RU/EN явно предупреждает о сбросе сада,
  опыта и статистики. Обычный текст подтверждения не изменять.
- Сбрасывать именно рабочий сад, а не изолированный DEBUG-сад. Существующие
  debugReset/debugShared и их защиту не ослаблять; тестовое пространство отдельно.
  Добавить узкий DEBUG-only путь с проверкой текущего режима непосредственно
  при действии. Не обходить настройки чтением сырых UserDefaults в UI.
- Перезаписать только садовый пакет новым состоянием ступени 1 через repository,
  не удалять UserDefaults-домен и не сбрасывать настройки/язык/музыку/сохранённую
  партию. Затем использовать существующий PlayerProgressManager.reset() и
  StatsManager.resetStats(), без новых формул и изменения форматов.
- Не допустить повторного начисления старого высокого уровня между сбросом
  дерева и XP: согласовать sourceLevel/максимум учёта и порядок переходов.
  Если запись свежего сада не удалась, не продолжать сброс XP/статистики,
  показать локализованную ошибку. Повторный сброс должен быть безопасным.
- После перезапуска приложения остаются пустой сад, 0 действий/XP, ступень 1,
  доступная первая посадка. Следующая полученная ступень даёт ровно одно действие.

Разработчик — чат «Ждать указаний руководителя». Узкие изменения: StatsView,
GardenManager, при необходимости GardenStateRepository, RU/EN и целевые тесты.
Остальной код защищён; руководитель код приложения не пишет.

Проверки без приложения/симулятора: сброс выращенного дерева с накопленными
действиями и высокой ступенью, сохранение/перезагрузка, бесплатная повторная
посадка, повторный сброс, следующая ступень без старых кредитов, ошибка записи;
статически проверить ветви testMode=false/Release, отмену и DEBUG-ограничение.
Проверять на памяти/отдельном тестовом хранилище, не вызывать сброс настоящих
данных владельца. По одной успешной Debug/Release-компиляции текущего этапа;
не повторять несвязанные тесты/симуляторы. Затем личная приёмка владельца.

## TD-03 — все посаженные деревья до максимума

Дополнение владельца: «дай мне кнопку в тест режиме — раскачать все на максы».
Выполняется вместе с RD-01H. В GardenView при DEBUG и текущем
SettingsManager.testModeEnabled показать кнопку «Все деревья до максимума» /
«Grow all trees to maximum». Область≥44 pt, прежний бумажный стиль.
В обычном режиме и Release кнопка/метод ускорения отсутствуют.

Действие доводит ВСЕ уже посаженные доступные виды до стадии10, без списания
действий, изменения XP/ступени/статистики и выбранного вида. Не сажает деревья
автоматически, не открывает ещё неподключённые виды. Пустой сад и все уже
максимальные деревья — без изменений (кнопка неактивна). Затем пользователь
может листать выращенные растения на главной. Ускорение сохраняется через
прежний repository, schema/storage keys не менять. При ошибке записи старое
состояние/архив сохраняются; существующая ошибка сада сообщается как прежде.

Непосредственно при нажатии менеджер повторно проверяет актуальный testMode;
нельзя вызвать ускорение рабочего сада при выключенном режиме. Новый путь
целиком #if DEBUG, остальные методы/правила роста и DEBUG-изоляция прежние.
Текущий тестовый сброс TD-02 по-прежнему возвращает рабочий сад к началу.

Узкие автономные проверки на памяти: два дерева разных стадий→10; баланс,
выбор/учтённая ступень/флаг бесплатности прежние; reload; повторный вызов;
пустой сад; ошибка записи. Статически проверить guard режима и Release-
исключение; реальные данные владельца не модифицировать проверками.
Добавить связанные unit tests без запуска XCTest/симулятора. Руководитель
компилирует Debug и Release один раз после реализации, затем приёмка владельцем.
