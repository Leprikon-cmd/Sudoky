# AGENTS.md

## Проект

«Судоку. Путь мудреца» — бесплатное офлайн-приложение Sudoku
для iPhone и iPad без рекламы, аналитики и встроенных покупок.

Фактический корень Git и Xcode-проекта: `Sudoky/`.
Основной проект: `Sudoky.xcodeproj`.

## Главная документация

Перед существенными изменениями прочитать:

`Sudoky/Проектная документация/Контекст проекта.md`

Если код и документация расходятся, сначала сообщить пользователю
о расхождении, а не исправлять его по предположению.

## Принципы работы

- Сначала изучить фактическое состояние связанных файлов.
- Делать небольшие и обратимые изменения.
- Не переписывать работающие части без необходимости.
- Не менять игровую механику за рамками поставленной задачи.
- Не менять сохранения и формат данных без отдельного согласования.
- Сохранять все посторонние локальные изменения пользователя.
- Не выполнять commit, push и публикацию без прямого разрешения.
- Не удалять файлы без подтверждения.

## Архитектура

- Интерфейс: SwiftUI.
- Основной подход: MVVM.
- Настройки должны проходить через `SettingsManager`.
- Шрифты должны выдаваться через `FontManager`.
- Локализация должна использовать существующий механизм `loc(...)`.
- Не дублировать функции существующих менеджеров.

## Локализация

Любой новый пользовательский текст необходимо локализовать.
Минимально поддерживать русский и английский языки.
При изменении существующего текста проверить остальные локализации.

## Проверка изменений

После изменения исходников:

1. Завершать каждый этап успешной компиляцией проекта, чтобы владелец
   мог запускать приложение в Xcode и контролировать промежуточный результат.
   Если сборка не проходит, этап не завершён и следующую задачу не начинать.
   После исправления ошибок повторить сборку; это не требует запуска
   несвязанных тестов. Ограничения окружения передавать руководителю
   для проверки в доступном окружении, не считать их успешной сборкой.
2. Не запускать и не использовать симуляторы: не устанавливать в них
   приложение, не просматривать интерфейс, не снимать скриншоты, не проводить
   UI-обходы и UI-тесты. Правило владельца от 10 октября 2026 обязательно
   для ВСЕХ агентов, включая руководителя. Ручную и визуальную проверку
   выполняет только владелец; агент сообщает, что ему посмотреть, и ждёт
   утверждения. Исключение требует нового прямого разрешения владельца
   на конкретную проверку.
3. При изменении связанной логики выполнять соразмерные программные проверки
   и доступные unit-тесты без симулятора. Если тесты требуют запуска
   симулятора, не запускать их автоматически: указать это в отчёте владельцу.
4. Для визуальных правок без изменения логики не запускать несвязанные
   тесты генератора; выполнять их перед крупной контрольной точкой.
5. Отдельно сообщить, что действительно проверено, а что проверить не удалось.

Компиляция для generic iOS Simulator SDK без запуска приложения допустима;
предпочитать generic destination, не выбирать конкретный симулятор/UDID.
Не повторять успешную сборку и проверки другим агентом без изменения
исходников или конкретной причины. Для изменений только документации
сборка и тесты не нужны. Краткий отчёт: что сделано, результат программных
проверок/сборки, что посмотреть владельцу. Следующий этап — после его приёмки.

Отсутствие визуальной проверки агентом не является блокером передачи
результата владельцу и не означает подтверждённую визуальную корректность.

## Границы задачи

Не расширять задачу самостоятельным рефакторингом.
Обнаруженные проблемы вне поставленной задачи перечислить отдельно.
